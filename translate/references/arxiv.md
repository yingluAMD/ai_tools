# arXiv 来源处理

用户提供 arXiv 链接、编号，或 PDF 中可识别出 arXiv 来源时读取本说明。这里只明确常见来源的获取原则，不要求实现专用下载器。

## 确认论文和版本

- 接受论文摘要页、HTML 全文页、PDF 链接和直接给出的 arXiv 编号；现代编号与旧式分类编号均可能出现，不只依赖本地文件名中的数字匹配。
- 用户给出版本时沿用该版本。未指定版本时，通过论文页面确认实际获取的版本，写入来源说明；同一任务的正文、PDF、图片与 LaTeX 源码应属于同一版本，不能静默混用。
- 本地 PDF 只有疑似编号时，核对标题和作者，避免误配另一篇论文。

## 获取完整正文

- 完整且公式、图片可用的 arXiv HTML 可直接整理为 `extracted.md`，保留章节、公式、正文图片、图注、表格与引用链接，进入主 skill 的 Step 2。摘要页不能替代全文。
- HTML 不存在、内容缺失或无法可靠提取时，下载同版本 PDF，走主 skill 的 Step 1 和 Step 1.5。HTML 仅局部缺失时，也可用同版本 PDF 核对补齐。
- PDF 公式提取有损或需要核对公式时，可获取同版本 LaTeX 源码；沿主文件的 `\input` / `\include` 关系查找公式，并展开所需自定义宏，不把源码中的注释或未启用的草稿当正文。
- 下载源码后先确认实际格式，可能是归档或单个 TeX 文件。解包到任务专用目录，先检查归档成员路径，不执行其中的脚本或构建命令；不把下载错误页面当作 TeX。
- HTML、PDF 或源码中某一路不可用时，选择仍可取得完整正文的分支；无法取得全文则说明限制，不编造缺失内容。

## 交付与续翻

沿用主 skill 的目录命名、逐段英中对照、术语表、图片保留和审校约定；大文档复用 `chunkctl.py`。在最终译文和断点背景中保留实际使用的 arXiv 编号、版本与来源 URL，便于续翻和内容核对。
